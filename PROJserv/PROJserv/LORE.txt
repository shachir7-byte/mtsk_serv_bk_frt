[1. ЭТАП 1: ЯДРО И БАЗА ДАННЫХ (PROJserv/APPserv/models.py)]
В основу положен жизненный цикл ремонта:
Приём -> Диагностика -> Согласование -> Ремонт -> Оплата -> Выдача.

Ключевые решения (28 моделей, сгруппированных в 6 бизнес-модулей):
1. Разделение уровней устройства:
   - DeviceModel: справочник моделей ("iPhone 13 Pro 128GB").
   - DeviceUnit: конкретный аппарат клиента или донор (IMEI, серийник).
   - DeviceSnapshot: техпаспорт состояния (плата, память, АКБ %, iCloud/FRP).
   - DeviceBundle: комплектация при конкретном приёме, привязана к RepairOrder.
2. Заказ-наряд (RepairOrder) без хранимой суммы total:
   - calculated_total, paid_total и balance_due вычисляются динамически через Sum()
     по работам (RepairWork), запчастям (InstalledPart) и оплатам (Payment) минус скидка.
3. Склад и доноры (Part, StockItem, StockMovement, InstalledPart, Donor):
   - Учет остатков по точкам (Terminal), атомарное списание через select_for_update().

-------------------------------------------------------------------
[2. ЭТАП 2: REST API ПО ПРОГРАММЕ КУРСА (views.py, urls.py, serializers.py)]
1. REST-проектирование:
   - Конечные множества в пути: /api/orders/period/{week|month|year}/{from_date}/
   - Фильтры поиска в query-параметрах: /api/clients/by-phone/?phone=...
2. DRF-стек:
   - ModelSerializer, ModelViewSet, DefaultRouter, perform_create(), @action.
3. Кэширование HTTP:
   - @cache_page(60 * 15) для справочников (DeviceModel, Service).
   - @never_cache для динамических данных (RepairOrder, Payment, Shift).
4. Безопасность:
   - TokenAuthentication + SessionAuthentication.
   - Кастомный IsEmployeeOrStaffPermission (BasePermission: has_permission + has_object_permission).

-------------------------------------------------------------------
[3. ЭТАП 3: БИЗНЕС-ЛОГИКА, ASYNC И WEBSOCKET]
1. Финансы (PaymentViewSet + ShiftViewSet + LedgerEntry):
   - Двойная проводка в LedgerEntry при оплате и возврате (/api/payments/{id}/refund/).
   - Зачёт кредита донора (/api/payments/apply-donor-credit/).
   - Закрытие и сверка кассовой смены (/api/shifts/{id}/close/).
2. Разбор доноров (/api/donors/{id}/disassemble/):
   - Оприходование снятых запчастей на склад точки с записью StockMovement.
3. Асинхронность (async_supplier_check):
   - Параллельный опрос 3 поставщиков через aiohttp.ClientSession + asyncio.gather().
4. WebSocket (Django Channels + Uvicorn):
   - ProtocolTypeRouter в asgi.py + OrderStatusConsumer на ws://127.0.0.1:8000/ws/orders/.
   - ASGIStaticFilesHandler для корректной отдачи статики админки под Uvicorn.
